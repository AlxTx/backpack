# Website Content Architecture

Use this skill to bridge strategy and design for public websites, landing pages,
marketing pages, local organization sites, and other content-led interfaces.

## Core principle

Before visual layout, decide what each page must help visitors understand and
what action it should make easier. A good site architecture is a sequence of
decisions, not a list of decorative sections.

## Required passes

1. **Site goal** — primary business/user outcome and success signal.
2. **Audience journeys** — what different visitors need first, second, and before
   taking action.
3. **Page inventory** — only pages that are useful, complete, and maintainable now.
4. **Navigation model** — clear menu labels, order, CTA placement, and footer
   grouping.
5. **Page purpose** — one job per page; avoid duplicate pages with the same role.
6. **Section narrative** — ordered sections with each section's purpose, key
   message, and action.
7. **Content readiness** — validated facts, placeholders to avoid, and content
   that must not be exposed yet.

## Navigation rules

- Header navigation should usually stay between 4 and 7 primary items.
- Use visitor-language labels over internal team labels.
- Do not expose empty, fake, or future pages.
- Put the main conversion CTA in a consistent, visible location.
- Footer can hold secondary/institutional paths that should not compete with the
  main journey.

## Section rules

- Start with the visitor's context, not the organization's autobiography.
- Educate before converting when the category is unfamiliar.
- Each section should answer one question or move one decision forward.
- CTA sections should match readiness: discover, receive info, contact, book,
  buy, or register depending on commitment level.
- Repeat important CTAs only when the page has earned the ask.

## Output expectation

When used inside product design, provide:

```txt
Content architecture:
- Sitemap / page list: ...
- Header navigation: ...
- Footer navigation: ...
- Primary CTA placement: ...
- Page roles: ...

Page narratives:
1. Page name / URL
   - Goal: ...
   - Visitor question answered: ...
   - Sections: [section name — purpose — key message — CTA]
```

## Do

- Keep the structure small enough to finish.
- Mark provisional content explicitly.
- Preserve existing URLs and page roles in brownfield unless the user asks to
  restructure.
- Produce a concrete section-by-section design handoff.

## Don't

- Do not create news, blog, team, staff, events, resources, or partner pages
  unless there is real content and a maintenance path.
- Do not bury the primary conversion behind generic "Learn more" paths.
- Do not use SEO architecture as an excuse to ship thin pages.
