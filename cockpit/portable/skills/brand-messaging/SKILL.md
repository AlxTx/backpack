# Brand Messaging

Use this skill to turn rough project context into a clear messaging foundation
before designing pages or writing final copy.

## Purpose

Clarify what the product, service, organization, or project needs people to
understand, believe, and do. This is not a campaign brainstorm or slogan factory.
It is the strategic message layer that informs site structure, copy, and UI.

## Required passes

1. **Audience map** — primary audience, secondary audiences, their intent, fears,
   questions, and readiness level.
2. **Core promise** — the plain-language outcome or value the site must make
   obvious.
3. **Message pillars** — 3-5 supporting messages that prove or explain the
   promise.
4. **Objections and reassurance** — what visitors may hesitate about and how the
   content should answer without overselling.
5. **Voice and tone** — clear do/don't guidance, with wording examples.
6. **Conversion language** — primary CTA, secondary CTA, and softer alternatives
   when commitment is premature.

## Greenfield defaults

- Prefer concrete, plain language over clever taglines.
- Explain unfamiliar categories before asking for commitment.
- For local/community projects, balance ambition with accessibility and trust.
- For serious brands, avoid hype, exclamation points, and childish phrasing.
- Make the primary CTA low-friction unless the user explicitly asks for hard
  conversion.

## Output expectation

When used inside product design, include a compact messaging block:

```txt
Messaging foundation:
- Primary audience: ...
- Secondary audiences: ...
- Core promise: ...
- Message pillars: ...
- Objections to address: ...
- Voice/tone: ...
- CTA language: ...
```

## Do

- State assumptions clearly when facts are missing.
- Use audience language, not internal jargon.
- Produce wording that can be reused directly in page copy.
- Preserve validated brand language in brownfield projects.

## Don't

- Do not invent proof points, numbers, testimonials, certifications, or claims.
- Do not turn every project into SaaS-style growth copy.
- Do not write final full-page copy if the site/page structure is still unknown.
